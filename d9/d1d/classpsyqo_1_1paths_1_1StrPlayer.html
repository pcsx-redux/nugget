Detailed Description

Streams an STR movie off the CD-ROM: MDEC video and interleaved XA audio.

The player only knows about a run of sectors: a start LBA and a sector count. Where they come from is the business of the helpers at the bottom of this file, which resolve an ISO9660 path or an archive entry into that pair.

The sectors are read in one continuous ReadS at double speed. Video sectors (the 0x0160 chunk magic at the start of their user data) are reassembled into frame slots straight from the CD-ROM interrupt, and XA-ADPCM audio sectors go to the SPU through the drive, without ever touching RAM. Frames are VLC-decoded with bsdec, run through the MDEC one 16-pixel column at a time, and each column is uploaded to VRAM while the next one decodes.

The player draws into psyqo's own double buffer, and presents through the normal frame() / flip cycle: call frame() from the scene's frame(), and it returns once the back buffer holds the next movie frame, so the flip that follows shows it. That means a scene playing a movie does nothing else while it plays, which is what the original libraries did too.

The GPU has to be configured by the application for the depth the player outputs: 24 bits per pixel by default, 15 bits with Options::rgb24 = false. In 24 bits, a 320 pixels wide frame occupies 480 halfwords of VRAM per buffer.

The CD-ROM device is owned by the player for the duration of the playback.

◆ frame()

psyqo::paths::StrPlayer::Status psyqo::paths::StrPlayer::frame ( )

Drives the playback, to be called from the scene's frame().

Blocks until the back buffer holds the next frame to present, then returns PLAYING. Returns ENDED once the stream is exhausted and every frame was shown, FAILED if the drive gave up, and IDLE when not playing.

void psyqo::paths::StrPlayer::stop ( )

Stops the playback early. The drive is paused and the buffers freed.

Call it from the main loop, between two calls to frame(), never from a callback: it pumps callbacks itself while it waits for the drive.
